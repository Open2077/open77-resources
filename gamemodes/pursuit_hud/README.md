# pursuit_hud

This resource draws the Pursuit match HUD for each player: their role, the queue position, the countdown and round timer, the bust and escape meters, the score, and for the runner the live separation and scanner age. It decides nothing; every value comes from [pursuit](../pursuit/) on the server through the `pursuit:matchState` and `pursuit:queueState` events.

- **Docs:** none yet
- **Starts:** on its own
- **Needs:** nothing
- **Runs on:** client

## Use it

Load it together with `pursuit`; the Pursuit template installs both. Enable and disable the two together, because a server that runs `pursuit` without this resource plays every match with no HUD. It is a separate resource so it can declare `reload_policy "reconnect"` for its WebUI page while the game rules keep `reload_policy "local"` and reload in seconds.

The HUD only interpolates the displayed time between server pushes. The server still decides when a round ends.

## Layout

Generated by `scripts/new-resource.ps1 -Kind hud` in the Open77 platform repository.

```text

```

## Rules for a HUD like this

- Fill in the manifest permissions: request only what the resource actually
  uses. A manifest permission grants access to a binding, it does not replace
  validating identity, distance, ownership or gameplay state.
- Keep authority on the server. Treat every client event and argument as
  untrusted input.
- Handle the `value, reason` result convention instead of assuming a game
  service is available.

See [The Lua resource runtime](https://open2077.net/docs/resource-runtime) and the
[server Lua API](https://open2077.net/docs/server-api).
